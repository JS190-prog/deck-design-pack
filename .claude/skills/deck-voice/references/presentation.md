# profile: presentation — 장표 텍스트 (발표덱·리딩덱)

> gongnyang/gn-voice `references/profiles/presentation.md`(MIT)를 옮겼다. 원저자 개인 문체 지시('공냥 터치')는
> 사용자 문체 가이드(`style-guide.md`)를 적용하는 규칙으로 바꿨고, 산문 지표 대신 `deck_voice.py gate`를 검사로 쓴다.

목적: 일반 글·아이디어를 **슬라이드에 들어가는 글**로 집필/변환. 근거 규범: Assertion-Evidence(PSU 통제실험 — 어써션 헤드라인이 이해도·회상 우위), Duarte 30/75단어 상한, 민토 피라미드.

**ppt-master 대응**: 헤드라인 = `design_spec.md §IX` 의 `Title`(문체가 토픽형이면 `Core message`), 키워드·불릿 = `Content`, 시각 지시 = `Visualization`/`Layout`, 노트 = `§X` 스피커 노트.

## 규칙 우선순위
1. **구조(이 문서)**: 한 장표 한 메시지, 제목만 읽어도 이야기가 흐름, 불릿 병렬, 장표와 대본 분리, 수치 날조 금지 — 문체 가이드가 있어도 지킨다.
2. **표면(`style-guide.md`)**: 끝맺음, 줄 길이, 장표당 어절 수, 마침표, 숫자·날짜 표기, 자주 쓴 표현 — 문체 가이드가 있으면 이 문서의 기본값보다 문체 가이드가 이긴다.
   - 예: 견본 제목이 토픽형(명사로 끝남)이면 제목은 토픽형으로 쓰고, 어써션(주장 완문)은 `Core message` 한 줄로 옮긴다.
   - 예: 견본 본문이 `~함/~임` 개조식이면 리딩덱 규칙으로 쓴다.
3. 문체 가이드가 없으면 아래 기본값(발표용)을 쓴다.

## 용도 분기 (미지정 시 발표용 기본)
- **발표용(청중 앞)**: 헤드라인 = 완문 어써션 1개(2줄 이내), 본문 = 키워드 3~5개(장표당 30단어 이내), 상세 서술은 전부 스피커 노트로.
- **리딩덱(결재·회람 장표)**: 개조식(명사 종결 "~함/~임" 통일) 허용 — 단 **장표 상단에 거버닝 메시지 한 줄 필수**, 다층 불릿 금지.

## 로직
1. **피라미드 설계 먼저**: 결론(거버닝 메시지) → 근거 3개 이내 → 증거. 도입 1장은 SCQ(상황→문제→질문).
2. **한 장표 한 메시지**: 인사이트가 둘이면 장표도 둘. 75단어 넘으면 그건 문서지 슬라이드가 아니다. 문체 가이드의 장표당 어절 수 범위를 넘으면 장표를 나눈다.
3. **헤드라인은 주장(완문)으로**: "2024 매출 현황"(토픽형) 대신 "2024 매출은 신제품이 견인해 18% 성장했다"(어써션형) — 문체 가이드가 토픽형이면 위 우선순위 2를 따른다. **헤드라인(또는 Core message)만 위에서 아래로 읽어도 스토리가 흘러야 한다**(타이틀만 읽기 테스트 — `gate` 출력의 `titles`로 자기검증 필수).
4. **불릿 병렬성**: 한 장표 안 항목은 동일 품사·동일 구조(명사형이면 전부 명사형). 하위 불릿 금지.
5. **대본 분리**: 슬라이드에 말할 문장을 복붙하지 않는다(청중이 읽으면 발표자 말을 못 듣는다). 서사·비유·구어는 스피커 노트에.
6. **시각 지시**: 헤드라인의 증거가 될 도표·이미지를 장표마다 한 줄로 제안(`[시각: …]`, ppt-master에서는 `Visualization`/§VIII).

## 출력 포맷 (덱 없이 장표 문구만 요청받았을 때 — `deck_outline.md`)
```
# [덱 제목] (용도: 발표용|리딩덱, N장)
## S1 — [헤드라인]
- 키워드 불릿 …
[시각: …]
(노트: 발표자가 말할 내용 — 여기에만 서사·구어 허용)
## S2 — …
```
`deck_voice.py`는 이 포맷을 그대로 읽는다(`## S1 —` 제목, `- ` 본문, `(노트: …)` 노트, `[시각: …]`은 무시).

## 문체 터치
- 문체 가이드가 있으면: 제목·본문은 가이드 "제목"·"본문" 규칙, 노트는 "발표자 노트" 규칙을 따른다. 가이드 "예문"은 리듬 참고용이며 그대로 베끼지 않는다.
- 문체 가이드가 없으면: 장표 본문은 격식 유지, 스피커 노트에만 말하듯(자문자답 전환, 수치 직삽).
- 오프닝 장표 헤드라인 하나는 통념 뒤집기·수치 훅 허용 — 단 본문이 갚을 수 있는 약속만.

## 금지
- 토픽형 제목 나열만으로 이야기가 끊기는 덱(토픽형 문체라면 Core message로 흐름을 잇는다), 개조식+어써션 혼용(한 덱 안에서 통일), 다층 불릿, 장표당 두 메시지, 슬라이드=대본 복붙, 근거 없는 수치.
- 산문 지표(gn-voice `verify_style.py`)는 장표 글에 맞지 않아 쓰지 않는다. 대신 `deck_voice.py gate`(역할별 밴드 + 금지 상투구 + 숫자 대조)와 ①타이틀만 읽기 ②장표당 어절 수 ③불릿 병렬성 자기검증으로 확인한다.
